## 9. 확정 정책·구현 시 확인 사항

- **확정:** 카카오페이 연동은 실연동 기준으로 구현하며 Secret key·CID는 설정으로 주입한다.
- **확정:** 멤버십은 30일 이용권을 사용자가 직접 재구매하는 방식이다. 자동 갱신·정기 청구는 후속 범위다.
- **확정:** 멤버십 이용권은 카카오페이로 직접 결제한다.
- **확정:** 30일 멤버십 이용권의 최초 구매·재구매 가격은 4,900원이다.
- **확정:** 멘토링은 마일리지를 유지하고 충전 수단을 카카오페이로 교체한다.
- **확정:** 마일리지 충전은 고정 패키지 선택 방식으로 제공한다.
- **확정:** 충전 결제 금액 1원당 1마일리지를 적립하고 보너스는 제공하지 않는다.
- **확정:** 충전 패키지는 5,000 / 10,000 / 30,000 / 50,000원 네 가지다.
- **확정:** 이용권은 유효기간 중 미리 재구매할 수 있으며 남은 기간을 보존하고 30일을 추가한다.
- **확정:** 멤버십 멘토의 정산 수수료를 감면하고 멘티 구매 가격은 유지한다.
- **확정:** 멘토 정산 수수료율은 일반 10%, 멤버십 5%다.
- **확정:** 신청 시점에 멘토의 멤버십 상태로 수수료율을 확정하며 진행 중 가입·만료와 관계없이 해당 건의 요율을 유지한다.
- **확정:** 배지는 멤버십 가입 표시이며 이용권 유효기간에 표시하고 만료 시 제거한다.
- **확정:** 배지는 사용자 프로필이 표시되는 모든 사용자 화면의 닉네임 옆에 표시한다.
- **확정:** 이용권 결제 취소는 후속 구매 여부만, 충전 결제 취소는 잔액 ≥ 충전액만 검사한다. 정지(`SUSPENDED`) 사용자의 결제는 기존 필터로 거부되며, 누적 이용 기간 상한은 두지 않는다.
- **확정:** 게시물 수정으로 제거된 멘션의 기존 알림은 유지하고, 숨김 게시물은 수정할 수 없다.
- **확정:** 배지는 작은 왕관 아이콘으로 표시하고 `멤버십 회원` 접근성 이름·설명을 제공한다.
- **확정:** 게시물은 본문 텍스트·해시태그·멘션만 수정하며 기존 이미지·영상은 유지한다.
- **확정:** 게시물 수정은 최초 게시 후 1시간 이내이며 수정 요청 시 멤버십이 유효해야 한다. 수정으로 가능 시간을 연장하지 않는다.
- **확정:** 게시물 수정은 게시물당 최대 1회이며 실제 변경 저장 시에만 횟수를 차감한다.
- **확정:** 수정 전 본문 보관·수정 이력 저장·조회·`수정됨` 표시를 구현하지 않는다. 최신 본문과 1회 제한에 필요한 정보만 유지한다.
- **확정:** 개발 단계이므로 수수료 도입 전 신청의 별도 호환 처리를 제외하고 새 신청을 기준으로 검증한다.
- **확정:** 결제 취소와 잔액·이용 기간 회수까지 구현하며 사용자 환불 화면·부분 환불·환불 기간 정책은 제외한다.
- **확정:** 멤버십·지갑은 `/membership`·`/wallet`로 분리하고 멘토링에는 잔액 요약·충전 바로가기·할인 안내를 남긴다.
- **확정:** 결제·카카오페이 연동은 `domain/payment`, 이용 기간·혜택은 `domain/membership`으로 분리하며 현재 서버·빌드 구조를 유지한다.
- **확정:** 결제 상태 모델(9개)·처리권·오류 분류·복구 실행(조회 시점 + 5분 스케줄러)·재호출 응답·결제 목록·결제 취소 권한(소유자 + 기능 플래그)·충전 취소 원장(`CHARGE_CANCEL`)은 6-2·6-6절과 7절을 따른다.
- **확정:** 이용권 취소 시작과 새 이용권 주문은 사용자 단위로 직렬화하고, 재로그인 시 승인을 재개하지 않는다.
- **구현 시 조정 가능:** 클래스·DTO·컬럼 이름, 화면 세부 배치. 동작·제약은 이 문서를 따른다.
- **후속 범위:** 실제 운영의 이용권·충전액 환불 조건과 이미 사용한 잔액·혜택 처리.
- **확정:** PC 결제창은 공식 권장 팝업 방식, 모바일 웹은 페이지 이동 방식이다(6-4절).
- **확인(공식 문서로 해소):** 사업자 등록 없이 개발자센터 앱의 Secret key(dev)로 연동할 수 있고, 이 키로는 http localhost·공인 IP 도메인을 등록할 수 있다. 전체 API 필드는 6-5절에 대조했다.
- **카카오페이 연동 확인 전 필요(개발 착수와 무관):** 개발자센터 앱 생성·사용 API(온라인 결제) 등록과 실제 서비스 도메인 등록, 실제 PC 팝업·모바일 복귀 동작, API 시각 필드의 시간대. mock 기반 개발·테스트는 이 항목 없이 진행한다.
- **후속 문서:** 구현 시 저장소별 README/API 명세·DB·Docker 공개 설정 예제 갱신.

## 갱신 기록

2026-10-10 1차 갱신은 현재 코드와 대조해 2절·정산 경로·마이그레이션 번호를 고치고, 10절을 추가하고, 결정 항목을 확정 반영하고, 카카오페이 개발자센터 공식 문서(온라인 결제 이해하기·단건 결제·주문 조회·결제 취소·부가기능·참고하기·전환하기, API 공통 가이드, 애플리케이션 관리)와 포럼 공식 답변을 대조해 6-2~6-5절을 보완한 문서 수정이다. 앱 소스·설정·DB·컨테이너는 변경하지 않았고 빌드·앱 테스트·실제 결제는 실행하지 않았다.

2026-10-10 최종안 갱신은 남은 결정 5건(충전 결제 취소 조건, 결제 상태 모델, 복구 실행 방식, 결제 취소 권한, 충전 취소 원장)을 확정해 6-6절을 추가하고, 문서 간 모순(결제 취소의 `사용` 조건)과 사실 오류(정지 판정 기준이 `user_penalties`가 아니라 `User.status = SUSPENDED`)를 고친 문서 수정이다. 검색 응답이 기존 사용자·게시물 DTO를 재사용함을 확인해 B2의 확인 항목을 해소했고, 프론트(`Sidebar.tsx`, `AuthContext.tsx`, `mentoring/page.tsx`, `next.config.ts`)·docker(`nginx/default.conf`, Compose `FRONTEND_BASE_URL`) 관련 서술을 현재 코드와 대조했다. 앱 소스·설정·DB·컨테이너는 변경하지 않았다.

2026-10-10 실연동 기준 갱신은 구현과 문서를 실연동 기준으로 맞춘 문서 수정이다. 결제 범위 표현을 상단 한 문장으로 모으고, 결제 취소 권한을 `소유자 + 기능 플래그(kakaopay.cancel-enabled) + 설정 CID 일치`로 바꾸고, Secret key·CID를 환경에 따라 주입하는 설정으로 정리했다.

2026-10-10 검토 반영 갱신은 검토 지적 8건을 반영한 문서 수정이다. approve·cancel의 4xx를 주문 조회로 판정하도록 오류 분류를 고치고(6-2절 12번), 상태 개수를 9개로 정정했다. 처리권에 `status_changed_at`을 포함하고, 재호출 응답·결제 목록 API·결제창 URL 저장을 추가했다(6-6절). 최초 멤버십 행 생성 잠금(M4), 이용권 취소와 새 주문의 직렬화(M8·6-6절), 재로그인 시 승인 재개 없음(6-3절)을 확정했다. `CANCELING` 복구에서 취소 미반영 시 외부 취소를 다시 호출하는 규칙과 `NEEDS_REVIEW` 수동 복구 기준을 추가했고, 8절 완료 기준에 검증 시나리오를 연결했다.

2026-10-10 API·검증 보완 갱신은 상품 목록 API(`GET /api/v1/payments/products`)와 결제 API 오류 HTTP 상태 표를 추가하고, 8절을 단계별 완료 기준으로 나누고(정산 공통화 중복 제거), PostgreSQL 동시성 테스트 환경변수(`PAYMENT_POSTGRES_TEST_*`)를 정하고, 오류코드 엑셀 대조 서술을 정정한 문서 수정이다. 개발 단계이므로 저장소 간 배포 순서는 정하지 않는다.
