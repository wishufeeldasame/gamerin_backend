# 이용권 수동 복구 기준 (#89)

04 문서 6-6절의 `NEEDS_REVIEW` 수동 확인 기준을 정리한다. 자동 복구 API나 관리자 화면을 추가하지 않는다.

## 복구 대상 확인

- 카카오페이 조회에서 해당 결제가 실제로 유지되는지, 저장한 주문·사용자·금액과 일치하는지 먼저 확인한다.
- 결제 상태만 보고 복구하지 않는다. `payments`, 해당 `membership_grants`, 현재 `user_memberships`를 함께 대조해 외부 결제는 유지되고 내부 기간만 회수됐는지 확인한다.
- 이미 복구한 건인지 운영 기록과 현재 기간을 확인한다. 결제·부여 이력을 삭제하거나 동일 결제로 새 부여 이력을 삽입하지 않는다.

## 기간 계산

회수했던 이용권 기간은 **복구 시점의 `max(now, expires_at) + 공용 상품 기간`**으로 계산한다. 현재 상품 `MEMBERSHIP_30D`의 기간은 30일이다.

- 현재 만료일이 5일 뒤라면 복구 후 만료일은 현재 시각의 35일 뒤다.
- 현재 만료일이 지났거나 현재 이용 기간이 없다면 복구 시각부터 30일이다.
- 과거 `granted_until`로 만료일을 덮어쓰지 않는다. 그 사이 승인된 다른 구매 기간이 사라질 수 있다.
- 단순 `grant` 재호출은 복구 수단이 아니다. 회수된 결제의 자동 재부여는 409로 거부한다.

## 적용과 사후 확인

- 결제 담당자가 외부 상태와 복구 대상임을 확인한 뒤 수동 적용한다. 해당 결제 행, User 행, 이용 기간 행 순으로 잠금을 맞추고 같은 트랜잭션에서 최신 만료일을 다시 읽어 기간을 계산한다.
- 원 주문과 과거 부여·회수 이력은 보존하며, 복구 결제 ID·근거·적용 전후 만료일을 운영 기록에 남긴다. 결제 상태 정정은 실제 결제사 상태와 취소 진행 여부를 함께 확인한 뒤 처리한다.
- 적용 후 `/api/v1/memberships/me`와 저장 기간을 확인한다. 혜택·배지는 이 만료일을 기준으로 조회 시점에 판정된다.
- 본 문서는 실제 DB에 변경을 실행하지 않는다. #86의 미완료 주문 검사·취소 복구와 통합 검증은 결제 담당 범위다.
